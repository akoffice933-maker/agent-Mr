# Руководство пользователя agent-Mr

Как работать с AI-оператором рекламы: от первого сообщения до подтверждённых
изменений в рекламных кабинетах.

## С чего начать

Откройте чат (главная страница) или Telegram-бота / MCP-сервер — это один и тот
же агент. Пишите обычным языком:

```
Покажи расходы за последние 7 дней
Сравни CPA между Google Ads и Яндекс.Директом
Сделай аудит всех кабинетов
Какие кампании тратят много, но плохо конвертируют?
```

Агент отвечает: данными (сводки, таблицы), выводами Advisor и — для действий,
влияющих на бюджет, — **предпросмотром с кнопками подтверждения**.

## Безопасность: как агент тратит (и не тратит) деньги

Правила, заложенные в код (не зависят от «настроения» LLM):

1. **Read-only по умолчанию.** До пока вы не включите управление на странице
   **Безопасность**, агент только читает данные и советует.
2. **Dry-run предпросмотр.** Любое действие, влияющее на бюджет, сначала
   показывается: что изменится (before/after), сколько это стоит в день,
   какие лимиты затрагиваются. Изменений нет до нажатия «Подтвердить».
3. **Лимиты расхода** (день/неделя/месяц, настраиваются на странице
   Безопасность). Превышение — действие блокируется, даже если вы подтвердили.
4. **Повторная проверка при подтверждении.** Лимиты пересчитываются в момент
   нажатия кнопки (могли исчерпаться другим пользователем/действием).
5. **Audit-log.** Каждое действие (и каждая попытка) пишется в журнал:
   кто, что, параметры, результат, trace шагов. Страница **Аудит**.
6. **Верификация у провайдера.** После выполнения агент перечитывает состояние
   у платформы (read-back) и помечает действие `VERIFIED` только если фактическое
   состояние совпало с целевым. В случае частичного создания (сбой на середине)
   агент сообщает, **что именно уже создано** на площадке, и предлагает
   продолжить (без дублей) или удалить созданные объекты.

## Управление

### Подтверждение действий

Предпросмотр показывает карточку:

- что изменится и где (площадка, кампания, сумма);
- кнопки **«✅ Подтвердить» / «❌ Отклонить»** (в вебе и в Telegram-инлайн);
- после подтверждения — статус `VERIFIED` (read-back совпал) либо
  описание частичного результата.

Ожидающие действия: чат-баннер / Telegram `/pending` / страница «Ожидает».

### Что агент умеет делать

| Команда (пример) | Действие |
|---|---|
| «Поставь на паузу кампании с CTR ниже 1%» | пауза нескольких кампаний (предпросмотр) |
| «Запусти «Поиск — Диваны на заказ»» | запуск конкретной кампании |
| «Подними ставки на 10% по кампаниям с конверсией» | корректировка ставок (предпросмотр) |
| «Добавь минус-фразы «бесплатно», «работа»» | минус-фразы в кампанию |
| «Продвинь объявления на Авито с низким числом просмотров» | продвижение (стоимость в предпросмотре) |
| «Создай кампанию в Яндекс Директ под названием «X», бюджет 300/день, группа «G», объявление: заголовок «…», текст «…», url …, ключи: …; минус-фразы: …» | создание кампании с деревом объявлений (полный spec) |
| «Удали созданную кампанию «X»» | удаление созданной агентом кампании (compensation) |
| «Примени все рекомендации» | применение рекомендаций аудита (предпросмотр) |

Создание кампании: имя кампании получает служебный тег вида
`agentmr:{org}:{действие}` — это делает повторные попытки **идемпотентными**:
если создание оборвалось (таймаут/сбой), повтор продолжит с того, что уже
создано, вместо создания дубля.

### Страницы

- **Отчёт** — кросс-платформенная эффективность (расход, CTR, CPA, ROI) +
  рекомендации Cross-Platform Advisor (куда перенести бюджет).
- **Кампании** — единый список кампаний/объявлений всех площадок с метриками;
  пауза/запуск кнопкой.
- **Аудит** — журнал всех действий агента (включая отклонённые и dry-run).
- **Безопасность** — режимы: «только чтение»/управление, лимиты расхода,
  подключение площадок (OAuth).

## Роли и права (multi-tenancy)

| Роль | Может |
|---|---|
| `owner` | всё, включая управление участниками организации |
| `admin` | всё, кроме управления участниками |
| `media_buyer` | пауза/запуск, ставки с рисковыми лимитами (≤±10% свободно, ±10–25% — с ограничением, >±25% — запрещено), бюджеты только с подтверждением |
| `analyst`, `viewer` | только чтение: отчёты, аудит, рекомендации |

Роли назначаются на организацию (`org_members`). Данные изолированы на уровне
БД (Postgres RLS): пользователь организации A технически не видит данных
организации B — это проверяется интеграционными тестами.

## Telegram-бот

Команды: `/start`, `/help`, `/report` (сводный расход), `/audit` (полный
аудит), `/pending` (действия, ожидающие подтверждения, с инлайн-кнопками).
Простые сообщения уходят в тот же агент, что и веб-чат.

## MCP-сервер

Для AI-агентов (Claude Desktop и др.) — те же возможности через 6 инструментов:
`agent_chat`, `list_pending_actions`, `approve_action`, `reject_action`,
`spend_report`, `list_campaigns`. Подключение — в README (раздел «MCP-сервер»).

## FAQ

**Агент ошибся в данных?**
Данные приходят из локального зеркала, синхронизированного с площадками.
Сверьте с кабинетом; при рассинхроне — `/report` и аудит покажут время последнего sync.

**Что произойдёт, если я нажму «Подтвердить» дважды?**
Второе подтверждение не примениется: действие уже исполнено (идемпотентность
статусов pending → executing → verified).

**Можно ли отключить LLM?**
Да — без `OPENROUTER_API_KEY` агент работает на детерминированном
rule-based парсере (поддерживает все команды из таблицы выше).

**Где хранятся OAuth-токены платформ?**
В БД, зашифрованные AES-256-GCM (`oauth_tokens`); в браузере/cookie их нет.
Ключ шифрования — `ENCRYPTION_KEY` из `.env` (храните отдельно от репозитория).

**Что такое «read-back VERIFIED»?**
После команды агент повторно читает состояние у платформы. Только совпадение
фактического и целевого состояния даёт статус VERIFIED; иначе действие
помечается `failed` с деталями — и локальное зеркало не меняется.
