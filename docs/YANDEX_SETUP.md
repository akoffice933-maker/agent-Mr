# Подключение Яндекс.Директа в production (День 1 из 14-дневного плана)

Пошаговый гайд: от нуля до «агент читает реальные данные вашего Директа».
Занимает 15–30 минут + время на одобрение заявки (обычно минуты, максимум сутки).

## 1. Создайте OAuth-приложение в Яндексе

1. Откройте <https://oauth.yandex.ru> (под аккаунтом Яндекса, к которому будет подключён Директ).
2. **Создать приложение**:
   - **Тип платформы**: `Веб-сервисы`
   - **Название**: например, `agent-mr`
   - **Redirect URI**: адрес, на который Яндекс будет возвращать после авторизации.
     - self-host: `https://ваш-домен/api/oauth/yandex`
     - локальная разработка: `http://localhost:3000/api/oauth/yandex` (Яндекс разрешает http только для localhost)
   - **Права доступа (scope)**: отметьте **«Яндекс.Директ — Использование API Яндекс.Директа»** (если такой scope есть в списке). Если список scope не содержит пункт Директа — оставьте как есть, доступ выдаётся заявкой (шаг 2).
3. После создания скопируйте **Client ID** и **Client Secret** (секрет показывается один раз — сохраните).

## 2. Подайте заявку на доступ к API Директа (обязательно!)

Созданного OAuth-приложения недостаточно — Директ требует отдельное согласование:

1. Войдите в <https://direct.yandex.ru> (в кабинете, где будет работать агент).
2. **Инструменты → API** (или прямой путь: <https://direct.yandex.ru/registered/main.pl?cmd=apiSettings>).
3. Вкладка **«Мои заявки»** → **«Новая заявка»**.
4. В форме: **Приложение** — выберите ваше OAuth-приложение; **Контакт** — ваш email. Отправьте.

Статус заявки виден там же. После одобрения приложение получает доступ к API именно от имени этого кабинета Директа.

> Если вам нужен доступ к Директу другого кабинета (агентства) — повторите шаг 2 в том кабинете с тем же OAuth-приложением.

## 3. Заполните `.env`

```env
YANDEX_OAUTH_CLIENT_ID=<ваш client id>
YANDEX_OAUTH_CLIENT_SECRET=<ваш client secret>
# Для локальной разработки без домена оставьте пустым — redirect сгенерируется как http://localhost:3000/api/oauth/yandex
PUBLIC_URL=http://localhost:3000

# Необязательно, но включается конверсии и осмысленный CPA (Метрика, шаг 4):
# METRIKA_API_KEY=...      # https://metrica.yandex.ru → Настройки → API-ключи
# METRIKA_COUNTER_ID=...   # id счётчика Метрики, где стоят цели
# METRIKA_GOAL_ID=1        # id цели-конверсии (по умолчанию 1)
```

## 4. Метрика для конверсий (CPA)

Директ сам по себе отдаёт клики/показы/расход; конверсии для осмысленного CPA берутся из Метрики:

1. В Метрике: **Настройки → API-ключи** → создайте ключ (scope: `statistic:read`).
2. Проверьте, что в счётчике есть **цель** (Goals), отражающая конверсию (заявка/звонок/покупка), и узнайте её id.
3. Задайте `METRIKA_API_KEY`, `METRIKA_COUNTER_ID`, `METRIKA_GOAL_ID`.

Адаптер синхронизирует поцельные визиты по дням (`/api/v2/statistics/website/visit`, метрика `reachedGoal`) и суммирует их с метриками Директа в `metrics_daily.conversions`.

## 5. Подключение в интерфейсе

1. Перезапустите приложение.
2. Страница **Безопасность → Площадки**: напротив «Яндекс.Директ» появится кнопка **«Подключить»**.
3. Нажмите — откроется страница авторизации Яндекса → **Разрешить**.
4. После редиректа: токен зашифрованно сохранён в `oauth_tokens`, режим аккаунта → `production`, агент сразу покажет онбординг: «Вот что я нашёл: N кампаний, расход за 7 дней, оценка аудита + 3 рекомендации».

## 6. Проверка

- **Безопасность**: по умолчанию включён режим «Только чтение» — агент отвечает, но не управляет. Включите управление явной галочкой.
- В чате: «Покажи расходы за последние 7 дней» — цифры должны совпадать с личным кабинетом.
- «Поставь на паузу кампании с CTR ниже 1%» → предпросмотр → **Подтвердить** → проверьте статус кампании в кабинете.
- Audit-log показывает каждую операцию с параметрами и ответом платформы.

## Безопасность

- Токены хранятся в БД, зашифрованные AES-256-GCM (ключ — `ENCRYPTION_KEY`); в коде и в логах токены не появляются.
- Refresh-токен обновляется автоматически при истечении access-токена.
- Отключить площадку: **Безопасность → Площадки → «В sandbox»** (режим переключится на демо-данные, токен останется и подключится снова кнопкой).

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `401 OAuth token invalid` | Токен истёк и refresh не прошёл — переподключите площадку |
| `403 Not authenticated` / «Нет доступа» | Заявка из шага 2 не одобрена или подана в другом кабинете |
| Ошибка redirect URI при авторизации | Redirect URI в приложении и `PUBLIC_URL` в `.env` должны совпадать точно (с хвостом `/api/oauth/yandex`) |
| Пустая статистика | Убедитесь, что в кабинете есть кампании с трафиком за последние 28 дней; Метрика подключена для конверсий |
